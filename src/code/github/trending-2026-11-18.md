## Modern Web Guidance 给 Agent 提供现代 Web 开发指南

上榜的 `modern-web-guidance-src` 存放指南的编写、校准和评估工具，供开发者使用的技能发布在 `modern-web-guidance` 仓库。开发者可以通过 CLI 搜索指南，也可以把技能接入编程助手，让助手在处理具体需求时检索相关资料。[源码仓库](https://github.com/GoogleChrome/modern-web-guidance-src#readme) · [发布仓库](https://github.com/GoogleChrome/modern-web-guidance#readme)

- **按需求查实现。** 指南覆盖 CSS 布局、原生表单与弹层、页面过渡、性能和无障碍等主题。可以用 `search` 按需求描述搜索，再用 `retrieve` 按 ID 读取某篇指南。例如，要实现会随组件容器变宽而重排的卡片，可以查 CSS 容器查询的用法。[官方文档](https://developer.chrome.com/docs/modern-web-guidance)
- **结合目标浏览器选方案。** 指南利用 Baseline 兼容性数据，帮助助手判断哪些能力可以直接用、哪些需要用 `@supports` 检测后渐进增强。这对于同时支持多个浏览器版本的项目尤其有用。[官方文档](https://developer.chrome.com/docs/modern-web-guidance)
- **梳理旧代码。** `legacy-scan` 对现有代码执行本地语法检查，找出可能值得替换的旧写法，再由 Agent 结合上下文判断哪些地方适合改。[官方文档](https://developer.chrome.com/docs/modern-web-guidance)

以移动端导航抽屉为例，官方指南区分了只在打开时显示的抽屉和桌面端还要常驻的侧栏。前者可以用原生 `<dialog>`，由浏览器处理 Escape 关闭和焦点恢复。抽屉的滑动交互可以用 CSS Scroll Snap 实现。这样的指南提供了具体的选型条件，也说明了组件需要处理哪些键盘行为。[导航抽屉指南](https://github.com/GoogleChrome/modern-web-guidance/blob/main/skills/modern-web-guidance/guides/ui-components/navigation-drawer.md)

### 安装到编程助手

CLI 发布包要求 Node.js 22 或更高版本。准备好 Node.js 和 npm 后，在终端运行安装向导，按提示选择你使用的编程助手。CLI 的安装方式支持自动更新。[npm 发布包](https://www.npmjs.com/package/modern-web-guidance) · [官方安装文档](https://developer.chrome.com/docs/modern-web-guidance/get-started)

```bash
node --version
npx modern-web-guidance@latest install
```

如果使用支持插件命令的 Codex CLI，也可以通过官方插件市场安装。两种方法选一种即可。安装后，在编程助手的新会话里明确要求使用 Modern Web Guidance。[Codex 安装说明](https://developer.chrome.com/docs/modern-web-guidance/get-started#codex)

```bash
codex plugin marketplace add GoogleChrome/modern-web-guidance
codex plugin add modern-web-guidance@googlechrome
```

### 第一次怎么用

可以先在终端查一篇指南。第一条命令返回匹配的指南及其 ID，第二条按示例 ID 打印指南正文。只试用检索时，可以直接运行这两条命令。[官方检索示例](https://developer.chrome.com/docs/modern-web-guidance/get-started#explore-before-installation)

```bash
npx modern-web-guidance@latest search "animate a dialog modal backdrop"
npx modern-web-guidance@latest retrieve "animate-to-from-top-layer"
```

在 Agent 会话里可以这样提需求。

> 用 Modern Web Guidance 帮我给设置弹窗加进入和退出动画。先列出查到的指南和涉及的浏览器能力，再说明旧浏览器会看到什么，最后检查键盘关闭与焦点恢复。

维护旧项目时，可以在项目根目录运行 `npx modern-web-guidance@latest legacy-scan .`，先看它列出的候选位置，再挑一个组件评估改动范围。适合从弹窗、表单或布局这类能单独验证行为的组件开始。[旧代码现代化工作流](https://developer.chrome.com/docs/modern-web-guidance/modernization-workflow)

## Plannotator 把计划批注和代码审查送回 Agent

Plannotator 为 Codex、Claude Code 等编程助手提供本地浏览器评审界面。它通过插件、钩子或命令接入 Agent 工作流。开发者在浏览器里针对原文或代码留下意见，再把这些意见连同对应位置一起发回会话。[项目 README](https://github.com/backnotprop/plannotator#readme)

- **评审计划和文档。** 可以选中 Agent 的计划、需求文档、Markdown 或上一条回复中的段落并批注。例如，在迁移计划的具体步骤旁要求补写老数据的处理方式。接好计划模式钩子后，Agent 提出计划时会打开评审界面。[计划评审说明](https://github.com/backnotprop/plannotator#plan-mode)
- **审查代码改动。** 在 diff 上逐行留言、提出修改建议，并把意见送回 Agent。它支持本地未提交改动、GitHub PR 和 GitLab MR。改动量大时，引导式审查可以把 diff 按主题组织起来，先看核心变化，再看连带改动。[代码审查说明](https://plannotator.ai/code-review)
- **评审页面和收集待决事项。** CLI 可以导入网页副本供批注，也可以通过 App Notes 扩展在实际页面上留言。Inbox 汇总多个 Agent 发来的问题、文件和待审内容，回复会返回发起该请求的会话。[文档与网页批注说明](https://docs.plannotator.ai/open-source/workflows/documents) · [项目 README](https://github.com/backnotprop/plannotator#readme)

### 安装 CLI 和 Agent 集成

完整安装需要 Git。Windows 在 PowerShell 中运行第一组命令，macOS、Linux 或 WSL 在终端运行第二组。安装后新开一个终端，运行 `plannotator --version`。能看到版本号就可以从命令行打开评审。用 Codex Desktop 的话，安装后也重启桌面应用。[官方安装说明](https://docs.plannotator.ai/open-source/start/installation)

```powershell
irm https://plannotator.ai/install.ps1 | iex
```

```bash
curl -fsSL https://plannotator.ai/install.sh | bash
```

自动弹出计划评审取决于 Agent 集成。按目前的官方说明，安装器可在 macOS、Linux 或 WSL 检测到 Codex 时配置实验性的 `Stop` 钩子。Windows 原生 Codex 使用下面的手动入口。[Codex 集成说明](https://docs.plannotator.ai/open-source/agents/codex)

### 第一次怎么用

1. 在项目根目录运行 `plannotator annotate README.md`。浏览器打开后，选中一段文字，留下一条批注，再点 **Send Feedback**。
2. 仓库里有未提交改动时，运行 `plannotator review`。在浏览器的 diff 里点具体代码行，写出预期行为。例如，表单提交失败后应当保留用户已输入的内容。
3. 直接从终端启动时，反馈会打印到终端，可以复制给 Agent。在 Codex 会话里，用 `!plannotator review` 或 `$plannotator-review` 发起评审，可以把反馈送回当前会话。[文档批注教程](https://docs.plannotator.ai/open-source/workflows/documents) · [代码审查教程](https://docs.plannotator.ai/open-source/start/code-review-quickstart) · [Codex 集成说明](https://docs.plannotator.ai/open-source/agents/codex)

## Astryx 提供 React 组件、主题和页面模板

Astryx 是 Meta 开源的设计系统，目前处于 Beta，要求 React 19 或更高版本。核心包提供带 TypeScript 类型的 React 组件，样式以预编译 CSS 分发，常规使用时导入样式并配置主题即可。项目文档列出了 150 多个组件，以及表格页、详情页和分步表单等页面模式。[项目 README](https://github.com/meta/astryx#readme) · [组件文档](https://github.com/meta/astryx/tree/main/packages/core#readme)

- **复用组件和页面结构。** 例如做一个订单管理页面，可以参考表格页模式组织列表和筛选区，再组合已有组件实现详情与表单。Storybook 可以直接浏览组件的不同状态。[Storybook](https://astryx.atmeta.com/storybook/)
- **统一品牌样式并按需定制。** 颜色、字号、间距和圆角这类设计令牌可通过 CSS 自定义属性调整，组件随主题变化。局部样式可以通过 `className` 覆盖。如果需要改写组件内部结构，CLI 的 `swizzle` 可以把组件源码导入项目，由项目自行维护。[组件文档](https://github.com/meta/astryx/tree/main/packages/core#readme)
- **让开发者和 Agent 查同一份资料。** CLI 可以搜索组件、查看属性和使用示例、列出模板或查设计令牌，也能输出结构化 JSON。比如在生成表单前，先用 `npx @astryxdesign/cli component Button` 查看当前组件用法，再按文档组合页面。[CLI 文档](https://github.com/meta/astryx/tree/main/packages/cli#readme)

### 安装到现有 React 项目

在已有的 React 19 项目根目录安装组件库、Neutral 主题和 StyleX 依赖。CLI 用来查文档和模板，可以按需安装。下面以 Vite 和 npm 为例。[核心包快速开始](https://github.com/meta/astryx/tree/main/packages/core#quick-start)

```bash
npm install @astryxdesign/core @astryxdesign/theme-neutral @stylexjs/stylex
npm install -D @astryxdesign/cli
```

在应用入口按顺序引入基础重置、组件样式和主题样式。例如，在 Vite 的 `src/main.tsx` 中加入以下导入。

```tsx
import "@astryxdesign/core/reset.css";
import "@astryxdesign/core/astryx.css";
import "@astryxdesign/theme-neutral/theme.css";
```

在 `src/App.tsx` 里，用 `Theme` 包裹组件树。先放一个按钮确认组件和主题样式已加载，再把 `Theme` 用到实际页面。

```tsx
import { Button } from "@astryxdesign/core/Button";
import { Theme } from "@astryxdesign/core/theme";
import { neutralTheme } from "@astryxdesign/theme-neutral/built";

export default function App() {
  return (
    <Theme theme={neutralTheme}>
      <Button label="保存设置" variant="primary" />
    </Theme>
  );
}
```

### 第一次怎么用

在 Vite 项目里运行 `npm run dev`，打开开发服务器给出的地址，确认按钮有主题样式并能用 Tab 聚焦。开始做页面时，可以用下面的命令查看按钮属性和现成模板。比如要做设置页，先查模板，再按文档组合需要的按钮、表单字段和布局。[核心包快速开始](https://github.com/meta/astryx/tree/main/packages/core#quick-start) · [CLI 文档](https://github.com/meta/astryx/tree/main/packages/cli#readme)

```bash
npx @astryxdesign/cli component Button
npx @astryxdesign/cli template --list
```

## Claude-BugHunter 为安全审查提供技能和报告模板

Claude-BugHunter 最初面向 Claude Code，采用 Agent Skills 格式。项目资料覆盖安全审查方法、公开漏洞报告归纳、发现的分级与报告整理。按上游文档的划分，公开案例可以作为审查参考，报告阶段则有专门的技能负责核对证据、整理影响和脱敏。[项目 README](https://github.com/elementalsouls/Claude-BugHunter#readme)

- **整理审查参考。** 项目按漏洞类别归纳公开报告，把常见问题和案例归为可按主题加载的技能。维护团队可以用这些资料对照已有安全审查单，识别需要人工复核的风险点。[项目功能说明](https://github.com/elementalsouls/Claude-BugHunter#whats-inside)
- **核对发现和影响。** 验证与报告技能帮助团队区分已证实的现象和待核实的推测，把受影响的功能、影响范围、严重性依据和可供复核的证据写进报告。[项目功能说明](https://github.com/elementalsouls/Claude-BugHunter#whats-inside)
- **整理证据和报告附件。** 项目提供报告模板和脱敏指导，覆盖截图、日志、HTTP 归档等材料。准备报告时，可以按指引遮盖会话凭据和个人信息，保留评审所需的证据。[项目 README](https://github.com/elementalsouls/Claude-BugHunter#readme)

### 在 Claude Code 里配置报告整理技能

如果你想先体验报告整理和证据脱敏，可以给已有的 Claude Code 项目加一个本地 `security-report` 技能。下面是一个可直接复制的示例，处理团队已经确认的问题和提供的材料。它使用 Claude Code 的项目级技能目录，输入斜杠命令时才会调用。[Claude Code 技能文档](https://code.claude.com/docs/en/skills)

在你的项目根目录新建 `.claude/skills/security-report/SKILL.md`，写入以下内容。

```markdown
---
name: security-report
description: 根据已确认的安全发现和脱敏材料起草内部修复报告。
disable-model-invocation: true
---

根据用户在会话里提供的材料，输出一份 Markdown 报告，包含：

1. 一句话标题与问题摘要。
2. 已确认受影响的功能、角色和影响范围。
3. 已有证据摘要，遮盖凭据和个人信息。
4. 修复建议、修复后的预期行为和复核项。
5. 还需要负责人确认的信息。

把无法从材料确定的内容标为“待核实”。
```

在该项目中打开 Claude Code，输入下面的示例。结果应包含确认的影响、预期权限规则和待核实事项，例如其他区域是否也受影响。

```text
/security-report 根据以下虚构的内部审查记录写报告：测试确认只读员工能打开含客户资料的导出页面。受影响的角色是只读员工，已确认范围是测试租户。预期只有管理员可以访问导出页面。
```
